# План доводки Hotline Circles

Цель: сначала воспроизводимая и стабильная игра, затем улучшение архитектуры и
контента. Переписывать всё с нуля или выбирать новый движок до проверки исходной
версии не нужно. Этапы ниже — план, а не уже реализованные возможности.

## Этап 0 — восстановить исходную точку ✅

- [x] Сравнить доступные файлы и выбрать рабочую основу.
- [x] Сохранить оригиналы и контрольные суммы.
- [x] Отделить разметку, CSS и JS, не меняя игровой код.
- [x] Убрать runtime-зависимость от CDN.
- [x] Уточнить запуск, структуру и упаковку ресурсов.
- [x] Добавить проверки исходников и workflow для GitHub.
- [ ] Пройти браузерный ручной чек-лист и сохранить список воспроизводимых багов.

## Этап 1 — надёжная игровая сессия (P0)

**Направления:** состояние игры, ввод, звук, переходы между экранами.

- Единая обработка `play()` Promise и ошибок загрузки MP3; тишина вместо ошибок.
- Сброс ввода при `blur`, потере видимости, паузе и выходе; mouseup вне canvas.
- Разделить ЛКМ и ПКМ.
- Централизовать переходы `menu / playing / paused / cutscene / gameover / complete`.
- Сбрасывать флаги режима и данные забега в одной точке; отменять устаревшие таймеры.
- Добавить браузерные тесты переходов, реального ввода и перезапуска.

**Готово, когда:** меню → выбор → игра → пауза → настройки → продолжить → смерть
→ рестарт → меню работают в обеих главах; HARD-MODE не влияет на новый обычный
забег; отсутствующая музыка не даёт необработанных ошибок; ввод не залипает.

## Этап 2 — экран и время (P1)

- Масштабирование виртуального игрового разрешения под окно с сохранением пропорций.
- Преобразование координат указателя из CSS-пикселей в игровые.
- Проверка меню и HUD на 1280×720, 1920×1080 и при изменении окна.
- Фиксированный шаг симуляции с ограниченным накоплением времени либо согласованный
  delta time; не смешивать несколько несовместимых систем таймеров.
- Таймеры боевых действий должны учитывать паузу и завершение сессии.

**Готово, когда:** прицел совпадает с указателем, важные кнопки доступны, движение
и кулдауны сопоставимы при разных частотах монитора и просадках FPS.

## Этап 3 — сохранения и удобство (P1)

- Версионированный `localStorage` для языка, громкости, разрешения и разблокировок.
- Определить с автором: все уровни доступны сразу или открываются последовательно.
- После решения — сохранять завершённые уровни и рекорды.
- Безопасные значения по умолчанию при повреждённом или недоступном хранилище.
- Полный RU/EN, справка по управлению, явный сброс сохранений с подтверждением.

**Готово, когда:** перезагрузка восстанавливает настройки; повреждение данных не
мешает запуску; правила прогресса понятны и согласованы.

## Этап 4 — модульная архитектура (P2)

- Зафиксировать браузерные регрессии перед изменением структуры.
- Вынести сначала чистые данные: оружие, персонажей, тексты и описания уровней.
- Затем отделять ввод, аудио, сессию, бой, AI, рендер и эффекты (карта в AUDIT.md).
- Убрать inline-обработчики HTML, после этого перейти на ES modules.
- При реальной необходимости добавить Vite, Vitest, ESLint; TypeScript внедрять
  постепенно, начиная с данных и состояния. React для Canvas-игры не обязателен.
- После каждой небольшой миграции сравнивать поведение со стабильной основой.

**Готово, когда:** изменения оружия не требуют правки меню и рендера; нет скрытых
глобальных зависимостей между подсистемами; регрессионные тесты проходят.

## Этап 5 — баланс и контент (P2)

- Пройти обучение всеми пятью героями главы 1.
- Проверить оружие, урон, боезапас, столкновения, спавн и поведение противников.
- Пройти всю главу 1, босса и последовательный HARD-MODE.
- Довести HoTRoD: кат-сцена, гранаты, бочки и финальная волна.
- Довести Skyward: края крыш, рывки, возврат на безопасную позицию, победа.
- Затем добавлять новые уровни, музыку и эффекты, а не раньше стабилизации основы.

**Готово, когда:** есть подтверждённое прохождение всех доступных уровней,
нет софтлоков, требования к новым уровням согласованы.

## Этап 6 — доставка и релиз (P3)

- Выбрать основной способ распространения: браузер, Windows или оба.
- Для браузера — отдельный артефакт только с `index.html`, `src/` и разрешёнными
  аудиоресурсами; архив старых сборок не выкладывать как часть игры.
- Проверить сборку pywebview / PyInstaller на чистой целевой Windows-машине.
- Добавить CI сборки релизных артефактов и инструкции обновления.
- Выбрать лицензию, подтвердить права на ресурсы, подготовить changelog.

**Готово, когда:** другой человек запускает игру по инструкции без ручного поиска
ресурсов; опубликованы только согласованные материалы.

## Как вести работу в GitHub

На каждый воспроизводимый баг — отдельная issue: шаги, ожидаемый результат,
фактический результат, ОС/браузер, скриншот или сообщение консоли. Приоритеты:
`P0` — ломает сессию, `P1` — мешает играть, `P2` — архитектура/контент,
`P3` — полировка/доставка. Это предлагаемая схема, labels и issues ещё не созданы.

Каждый pull request должен решать ограниченную задачу и содержать описание
проверок. Не смешивать баланс оружия, новый уровень и переделку архитектуры в одном
изменении. Исходный архив не редактировать. Workflow добавлен в репозиторий;
его реальный запуск на GitHub произойдёт после отправки изменений.

**Предложение для следующей задачи:** «Стабилизация сессии: безопасный запуск
музыки, сброс ввода и выход из HARD-MODE». Это полезнее немедленного переноса
на новый движок и даст надёжную базу для следующих улучшений.
