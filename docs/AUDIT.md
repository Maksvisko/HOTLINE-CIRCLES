# Разбор исходных материалов

Дата: 24 ноября 2026. Аудит выполнен по доступным вложениям и исходникам;
дата в имени «ПОСЛЕДНЯЯ ВЕРСИЯ» не использовалась как доказательство новизны.

## 1. Версии и назначение файлов

В списке вложений было 12 позиций, но в каталоге загрузок доступны **9 уникальных
имён**. Повторные `game.py`, `warn` и `xref` не доступны как отдельные экземпляры;
сравнить потенциально разные файлы с одним именем невозможно.
Все 9 доступных файлов сохранены байт-в-байт. Контрольные суммы — в
[`archive/manifest.json`](../archive/manifest.json).

Выбрана более полная версия с корректной организацией музыки в `audio/`.
Слияние игровой логики между версиями не выполнялось: две новые версии эквивалентны

Отчёты PyInstaller не доказывают, что сборка сломана: там есть опциональные,
платформенные и условные импорты. Не нужно устанавливать всё из `warn` подряд.
В отчётах присутствуют исторические локальные Windows-пути; перед публикацией
архива стоит проверить, устраивает ли автора раскрытие этой информации.

## 2. Как устроена игра

Игра написана на обычном JavaScript и Canvas 2D, без игрового фреймворка.
Python лишь открывает HTML. Библиотека Tailwind использовалась ради трёх классов
HUD; её внешний CDN заменён локальными правилами, без добавления сборщика.

| Подсистема | Ориентиры в `src/game.js` | Будущая граница модуля |
|---|---|---|
| Общие данные и состояние | `player`, `weapons`, массивы сущностей, `gameState` | `core/state`, `data/weapons`, `data/characters` |
| Меню и локализация | `setLanguage`, `renderChapterSelect`, `selectCharacter*` | `ui/menus`, `ui/i18n` |
| Ввод | обработчики `keydown`, `keyup`, `mousedown`, `contextmenu` | `core/input` |
| Звук | `initAudio`, `playSound`, `startHtmlMusicForLevel`, `stopMusic` | `audio/manager` |
| Жизненный цикл | `startGame`, `initLevel`, `restartLevel`, `levelComplete` | `core/session`, `core/scenes` |
| Уровни | `createWalls`, `createEnemies`, `createHotrodRoom`, `createSkywardLevel` | `levels/` и описания уровней |
| Бой | `shoot`, `useAbility`, `updateFlame`, `updateMeshGrenades` | `systems/combat`, `systems/abilities` |
| Противники | `createEnemy`, `findPath`, `updateBoss`, `updateMiniBoss` | `entities/`, `systems/ai` |
| Рендер и эффекты | `draw`, `drawWeapon`, `drawAmbient`, `drawHotrodCutscene` | `render/`, `effects/` |
| Основной цикл | `gameLoop`, `update` | `core/loop` |

Внутренние ID: обучение — `0`, глава 1 — `1…5`, HoTRoD — `101`, Skyward — `102`.
В главе 2 уже есть две реализации уровней и заглушка следующего. Это не только
пункты меню, но их полное прохождение и баланс пока не проверены.

JS оставлен обычным скриптом, а не `type="module"`: существующие inline-обработчики
HTML вызывают глобальные функции. Мгновенный перевод на ES modules сломал бы их.

## 3. Что уже изменено при разборе

- Все доступные вложения сохранены с исходными байтами и SHA-256.
- HTML, CSS и JavaScript физически разделены. Код JS совпадает с исходным блоком.
- Внешний CDN удалён; три используемые утилиты HUD определены в локальном CSS.
  Полную визуальную эквивалентность без Tailwind Preflight нужно проверить вручную.
- Оболочка ищет ресурсы относительно самого файла, поддерживает `_MEIPASS`;
  импорт GUI выполняется только при запуске. Добавлены два теста путей.
- Добавлены локальные проверки, GitHub Actions и документация.
- Музыка, новые уровни и новые зависимости игрового движка не добавлялись.

## 4. Проблемы и риски

Ниже отдельно обозначены факты исходного кода и гипотезы для воспроизведения.

### Высокий приоритет

1. **Отсутствуют MP3 (факт).** Все шесть путей ссылаются на непредоставленные файлы.
   Вызовы `audio.play()` обёрнуты в синхронный `try/catch`, который не ловит отказ
   Promise. Нужна единая обработка отсутствующего файла и запрета autoplay.
2. **Сброс ввода неполный (факт кода / симптом требует воспроизведения).**
   `mouseup` слушается на canvas, нет общего сброса клавиш при потере фокуса.
   Возможны продолжающаяся стрельба и движение после ухода курсора / Alt-Tab.
   `mousedown` не фильтрует кнопку мыши: проверить, не стреляет ли ПКМ одновременно
   с активацией способности.
3. **Смешаны кадровые и реальные таймеры (факт).** Скорость, кулдауны и эффекты
   меняются на кадр, другие действия идут через `setTimeout` / `Date.now`.
   Цикл ограничивает частоту до 60, но не компенсирует пропущенные шаги при низком FPS.
   Отложенные действия не привязаны к жизненному циклу сессии; проверить их после
   паузы, рестарта и выхода в меню.
4. **Режимы используют общие флаги (риск по коду).** HARD-MODE, главы и выбранные
   уровни меняют глобальные переменные в разных функциях. Проверить отмену выбора,
   возврат из HARD-MODE в обычную игру, смерть и перезапуск главы 2.
5. **Размер canvas и окна различаются (факт).** Стартовый canvas — 1920×1080,
   десктопное окно — 1280×720; адаптация меню частичная. Координаты мыши вычисляются
   без коэффициента CSS/внутреннего разрешения. При введении CSS-масштабирования
   обязательно исправить прицеливание, а не просто сжать canvas.

### Следующий приоритет

- **Нет постоянного хранения:** не найдены `localStorage` или другая система записи
  настроек, разблокировок и прогресса.
- **Перевод неполный:** есть RU/EN-таблицы, но часть сообщений, названий и подсказок
  зашита по-русски. Язык настроек ещё не означает полную локализацию игры.
- **Сильная связность:** большие `update` / `draw`, глобальные сущности, изменяемые
  шаблоны оружия. Перед разделением нужны тесты поведения, а не только синтаксиса.
- **Сборка:** старый README не добавлял ресурсы в exe; пример исправлен, но новая
  сборка на целевой Windows-машине ещё не выполнялась.
- **Права на ресурсы и название:** не найдена лицензия; происхождение будущей музыки
  и допустимость использования чужих материалов нужно проверить до релиза.

## 5. Что проверено и что нет

Прошли 8 проверок исходников и архива плюс 2 теста путей оболочки.
Разбор `node --check` проверяет синтаксис, но не выполнение браузерных API.

Запущен HTTP-сервер для Live Preview. Попытка браузерного smoke-теста в headless
Chromium остановилась **до открытия игры**: в окружении отсутствует `libnspr4.so`.
Поэтому нет подтверждения реального рендера, работоспособности каждого уровня,
отсутствия runtime-ошибок или полного прохождения. Эти пункты нельзя считать
пройденными на основании статических проверок.
